# 自选股刷新稳定性设计

## 问题

Windows 下东方财富请求失败后会转用 curl。旧实现使用
`subprocess.run(text=True)`，由系统代码页解码输出。curl 返回 UTF-8
错误信息时，后台读取线程可能解码失败并把 `stdout` 留为 `None`；
随后 `.strip()` 抛出 `AttributeError`，本地 HTTP 连接被直接关闭，
浏览器只能显示 `Failed to fetch`。

## 方案

1. 所有 curl 调用统一使用二进制输出，再按供应商编码容错解码。
2. curl 超时、空输出和非零退出码统一转成 `OSError`，进入既有数据源
   降级链，不让传输实现异常穿透到 HTTP 层。
3. 刷新接口隔离快照源异常；报价仍按东方财富、腾讯、新浪顺序补齐。
4. 最近一次当日已核验报价写入带摘要校验的本地缓存。实时源瞬断时，
   只在配置的短有效期内回放，并标记为 `latest_available` 和
   `verified_quote_cache:<原来源>`。
5. 前端手动刷新使用配置化超时和有界重试；失败时保留现有页面，
   不把空结果覆盖到自选股。
6. HTTP 最外层把未预期异常转换成结构化 503，避免连接无响应断开。

## 数据真实性边界

- 缓存只接收价格有效、交易日为当天的已核验报价。
- 缓存回放不标记为 `real_time`，保留原始交易时间。
- 过期缓存和上一交易日缓存不得补作当前报价。
- 资金流、板块和盘口不会由报价缓存推断。

## 验证

- 非系统编码字节不会触发 reader thread 解码崩溃。
- `stdout=None` 转为可恢复的 `OSError`。
- 快照客户端异常时刷新仍可从备用报价源完成。
- 所有实时源失败时可回放短时当日缓存且来源标签正确。
- 全量后端测试和前端 JavaScript 语法检查通过。
