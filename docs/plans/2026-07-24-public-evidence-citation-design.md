# 用户可读证据引用设计

## 问题

模型解释把 `source id`、`as_of` 等内部审计字段直接展示给用户；同时前端将 Markdown
作为纯文本输出，导致引用含义不清、章节层级混乱。

## 设计

- 审计层继续保存稳定的 `EvidenceSource.id`，不破坏回放、评价和来源追踪。
- 模型输入只提供由报告生成的中文引用：
  `【证据名称｜来源机构｜数据截至 日期】`。
- 模型输出进入报告前再次清洗；旧报告在公开展示时也执行同一转换。
- 未解析的内部来源不直接暴露，统一显示为 `【待核验证据】`。
- 来源名称与引用格式放入运行时配置，不在业务逻辑中硬编码。
- 前端用 DOM 文本节点安全渲染标题、列表、加粗和引用标签，不使用 `innerHTML`。

## 验收

- 页面不出现 `source id`、`source_id`、`as_of`。
- 用户能直接看懂证据是什么、来自哪里、数据截至何时。
- 原始报告中的内部来源 ID 保持不变。
- 未知来源不得被包装成已核验证据。
