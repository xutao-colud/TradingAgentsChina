# 3–10 人真实数据测试版设计

## 目标

把当前单用户本地研究台收敛为可供 3–10 人试用的小型产品。测试版仍不是正式认证系统，但必须做到：

- 登录页明确标注“测试访问，账号密码尚未校验”。
- 密码只用于非空表单校验，不保存、不记录、不返回。
- 每个账号别名使用独立本地 Memory 目录，避免自选、持仓、画像和报告相互串写。
- Web 端只允许 `production` Provider；生产链路不得回落到样例数据。
- 用户数、并发研判数、会话时长和浏览器密钥配置能力都来自版本化配置。
- 页面展示的活跃用户、研判数量和模型解释数量全部来自服务进程真实计数，不使用演示数字。

## 方案选择

采用“进程内测试会话 + 每用户 LocalMemoryStore + 有界研判门禁”。

没有选择纯前端登录遮罩，因为它无法保护 API，也无法隔离用户数据。没有直接接入 PostgreSQL/OAuth，因为当前目标是 3–10 人功能测试，正式身份认证和多实例部署属于下一阶段。

登录后服务生成随机 HttpOnly Cookie。账号别名经规范化和哈希后只用于选择 `memory/users/<user-id>`，原始账号仅保存在有过期时间的进程内会话中。服务重启后所有测试会话失效，但各用户 Memory 保留。

## 资源与数据边界

- 活跃测试用户：最多 10。
- 同时运行的重研判/机会扫描：最多 2。
- 实时 ticker 继续走轻量报价链路，不占重研判名额。
- LLM 单次输出预算沿用配置中的 `llm_request`，不由页面写死。
- `SampleMarketDataProvider` 仅保留给单元测试和显式离线回归；小型 Web 测试服务拒绝以 sample Provider 启动。
- 数据源不可用时保持“数据不足”，不得构造默认行情、默认资金、默认胜率或默认结论。

## HTTP 与页面流程

1. `GET /api/session` 返回当前测试会话状态和真实容量指标。
2. `POST /api/session/login` 接受非空账号、非空密码；不校验凭据，创建测试会话。
3. 除健康检查和会话接口外，所有 `/api/*` 都需要有效 Cookie。
4. `POST /api/session/logout` 清除进程内会话和 Cookie。
5. 未登录时只显示双栏登录页；登录后显示研究工作台、测试模式标识、当前账号和真实运行指标。
6. 浏览器模型密钥配置在小型团队模式下默认关闭，只允许部署环境变量提供密钥。

## 验证

- 配置校验测试：用户上限、并发上限、会话期限必须为正。
- 会话测试：非空凭据可进入、密码不保存、超过用户上限被拒绝、退出后 Cookie 失效。
- 隔离测试：两个账号的自选和 TradingProfile 位于不同目录。
- 并发测试：超过配置的研判立即返回繁忙，不无限创建重任务。
- HTTP 测试：未登录 API 返回 401；登录、访问、退出流程完整。
- UI 验证：桌面和窄屏下登录页、密码显隐、测试警告、退出入口均可用。
